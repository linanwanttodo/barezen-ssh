## 第一层 · 全局约束

### 0. 产品与技术栈概述

BareZen-SSH 是自研**跨平台桌面 SSH 客户端**（Kotlin + Compose Multiplatform Desktop），单用户本地自用，纯中文界面。成功标准：日常运维全程无需再打开其他 SSH 工具。

技术事实（设计必须兼容，但不要求你实现）：

| 层 | 现状 |
|---|---|
| UI 框架 | Compose Desktop（JVM），窗口 ≥1180 宽，Wayland / Windows / macOS |
| SSH / SFTP / 端口转发 | sshj 库 |
| 终端渲染 | JediTerm（Swing 组件内嵌 Compose），见 §4 |
| 凭据存储 | 规划为系统钥匙串（Linux Secret Service / Windows CredMan / macOS Keychain） |
| 架构 | 功能层（连接、仓库、终端会话）与 UI 层解耦——**新设计只需覆盖本清单的能力，底层均可支撑** |

实现状态标记：**✅ 已实现** = 当前代码真实可用；**📋 愿景** = 已批准的规划（标注里程碑 M2/M3/M4/M5），设计时须为其预留布局，但不必假装数据已存在。

原 MaidKit 复刻规格的以下约束**全部作废**，由你自由提案：

- ~~间距 4/8/12/16/24/32 栅格、边框层次不靠阴影等规则~~
- ~~UI 正文字体使用 JetBrains Mono~~
- ~~左侧 NavigationRail + 六目的地的信息架构、现有对话框 / 横幅 / 状态栏的形态~~
- ~~1:1 参照任何现有产品的视觉~~（新设计须为原创提案，不整体复制任何 AGPL 产品的视觉）

**你可以自由决定**：配色（明/暗/跟随系统策略均可提案）、字体、版式、组件形态、导航结构、页面划分、层级、动效风格、对话框与通知形态。

**你必须交付**：自洽的设计语言声明 + 每处颜色组合的对比度证据（见附录 B）。建议至少提供一套暗色方案（终端使用场景惯例），非硬性要求。

### 2. 平台与语言硬约束

1. **桌面应用**，最小窗口宽 1180px；设计须给出 ≥1180 的下限布局与推荐宽（如 1440 / 1920）布局。
2. **纯简体中文界面**，无英文 UI 句子（技术值、主机名、命令、代码除外）。
3. **键盘可达**：所有操作可 Tab 到达，Tab 顺序符合视觉顺序，焦点环可见。
4. **色彩不作唯一状态指示**（状态须另有文字或图形冗余）。
5. 所选字体与图标必须为**可随应用打包分发**的开源许可资源（不依赖用户系统必装字体）。
6. 动效仅用于状态传达（150–250ms 量级），必须尊重 `prefers-reduced-motion`（减弱时仅保留非位移式反馈）。
7. 无障碍达标 **WCAG AA**：正文 ≥4.5:1，大字 ≥3:1。

### 3. 性能与非功能

- 冷启动 < 2s；终端滚动 60fps 目标。
- 设计不得引入高频重绘的装饰性动画（如常驻粒子、呼吸光晕）拖累渲染。

### 4. 终端技术硬点（不可协商）

1. 终端区是**内嵌 JediTerm 的可滚动等宽渲染区**——任何页面方案都必须容纳一块完整的、可独立滚动的矩形区域（其内容是真实 shell 输出，不可用网页元素模拟）。
2. 终端等宽字体 **JetBrains Mono，13px 基准**（此项为唯一锁定的字体场景；字号可随「设置 · 终端字体」愿景项演化）。
3. 终端配色经 JediTerm `SettingsProvider` 注入——**终端内部 16 色调色板独立于 UI 主题**，设计师可给终端调色板方案，但它不从 UI 主题自动派生。
4. 终端随窗口/分屏格子尺寸自适应；支持多标签、向右/向下分屏（见 §5-终端 D1/D2）。
5. 终端底部/周边状态信息须有承载位（现状：连接状态 + SSH 往返延迟 ✅；愿景：+ 负载 / 内存 / 运行时间 📋）。

### 5. 安全红线（设计文案不得违反）

1. **登录密码、私钥口令只存内存，绝不落明文数据库 / 不进日志**。任何 UI 文案不得暗示「保存密码到本地文件」。
2. 规划中凭据引用进**系统钥匙串**，界面须明示「已存入系统钥匙串」。
3. 首次连接未知主机允许写 known_hosts（TOFU 指纹确认为规划中的交互）；导出连接默认脱敏。
4. AI 助手的 API Key 存系统钥匙串（愿景）。

### 6. 通用交互骨架（模式存在，形态自由）

以下**交互模式**是功能真相的一部分，你必须为其设计形态，但长相完全由你定：对话框、横幅提示、底部/顶部状态条、列表空态、加载态、错误态 + 重试、操作确认、进度指示、通知。IA（这些模式挂在哪、怎么组织）同样开放。

## 第二层 · 能力域

> 以下七个能力域是**功能真相的分组**，不是导航结构要求——你可以合并、拆分、重组页面，但清单内每项能力都必须在你的设计中有可达位置（或明确标为分期占位）。

### 域 1 · 服务器管理

**职责**：管理 SSH 目标主机并发起连接。产品第一入口。

**功能清单**
1. 服务器列表：名称、地址:端口、标签、连接状态、延迟；（📋M4）卡片微瓦片：平均负载 / 内存 / 运行时间 + 操作按钮。 ✅
2. 新建服务器：名称 / 地址 / 端口（默认 22）/ 用户名 / 认证方式（密码 | 私钥）/ 标签。 ✅
3. 编辑服务器（同一表单复用）。 ✅
4. 删除服务器（含确认）。 📋（愿景 A1「增删改查」之「删」，当前未实现）
5. 搜索：按名称、地址或标签过滤。 ✅
6. 标签过滤：多选 chips。 ✅
7. 未连接汇总横幅「N 台服务器未连接」。 ✅（形态自由）
8. 「全部重连」横幅操作。 📋（原型愿景）
9. 发起连接（→ 域 2 连接对话框）。 ✅
10. 从此域直达：新建终端 → 域 3 ✅；打开文件管理 → 域 4 ✅（入口壳已存在，功能 📋M2）；查看仪表盘/刷新统计 → 域 6 📋。

**入口与到达路径**
- 主导航（结构由你设计）→ 服务器域（默认首屏建议，可提案）。
- 屏内：新建（现状为悬浮按钮）、卡片/行内编辑与操作。
- 出口：连接 → 连接对话框 → 终端域；打开文件管理 → 文件域；仪表盘 → 仪表盘域。

**状态与异常**
- 空列表（零服务器）：空态 + 新建引导。
- 搜索无结果：空态。
- 连接失败：错误呈现 + 「重试」（进域 2 状态机）。
- 删除确认（📋）：破坏性操作需确认。

**数据实体**：`Server { id, name, host, port, user, tags[], auth(密码|私钥), state, latencyMs, stats? }`

**实现状态**：✅ 列表 / 搜索 / 标签过滤 / 新建 / 编辑 / 连接 / 三个直达入口；📋 删除 / 全部重连 / 卡片统计瓦片。

### 域 2 · SSH 连接与会话

**职责**：认证、连接生命周期、会话语义。多数情况下它是「到达终端前的一段流程」而非常驻页面。

**功能清单**
1. 连接对话框：目标为「连接到 <服务器名>」，认证方式二选一：
   - 密码：用户名 + 密码输入。 ✅
   - 私钥：私钥路径 / 「选择私钥文件」文件选择器 + 可选私钥口令。 ✅
   - 操作：连接 / 取消。 ✅
2. 生命周期状态机：连接中 → 已连接 / 连接失败；未连接；断开。 ✅
3. 状态文案：「正在连接 <名>…」「连接中」「已连接 · <N> ms」「连接失败：<原因>」「重试」。 ✅
4. SSH 往返延迟探测与显示。 ✅
5. 断线自动重连。 📋（愿景 A4）
6. 显式「断开连接」入口：**现状无**——设计可自由提案（推荐提供，见交接说明开放项）。
7. 凭据引用走系统钥匙串（连接对话框不再直接见明文存储）。 📋（A2/C3）
8. TOFU 指纹确认（首次连接未知主机时询问）。 📋（愿景；当前自动接受并记入 known_hosts）

**入口与到达路径**
- 服务器域「连接」按钮 → 弹出/进入连接流程 → 成功后进终端域。
- 终端域断开/失败后的重连入口（形态自由）。

**状态与异常**
- 连接中（可取消）；失败（展示 sshj 原因 + 重试）；成功（直达终端）；重试期间防重复提交。
- 已连接会话的延迟是持续指标，供状态栏引用（域 3）。

**数据实体**：`Connection { serverId, state(未连接|连接中|已连接|失败), latencyMs, startedAt, authMaterial(仅内存) }`

**实现状态**：✅ 1–4；📋 5、7、8；6（显式断开入口）为开放项。

### 域 3 · 终端（核心域，含标签/分屏/AI 侧栏愿景）

**职责**：真实 shell 交互的场所，产品价值中心。

**功能清单**
1. JediTerm 渲染区：真实 shell 输出、可滚动、随窗自适应；输入直通 SSH。 ✅
2. 键盘/选择行为：JediTerm 默认选择与复制粘贴；（📋 设置愿景）「选中即复制」「Shift+Insert 粘贴」「sudo 密码自动填入」开关。 ✅ 核心 / 📋 开关
3. 空态：未选择会话时提示「在服务器列表选择『新建终端』以开始。」 ✅
4. 状态栏：连接状态 + 服务器名 + SSH 往返延迟 ✅；+ 负载 / 内存 / 运行时间 📋M4（依赖指标采集）。
5. 多标签：新建 / 关闭 / 中键关闭 / 切换；标签含图标与服务器名。 📋M4（D1）
6. 分屏：向右 / 向下拆分，每格独立终端。 📋M4（D2）
7. **AI 运维侧栏（M5 愿景，E1–E8 摘要）**：终端右侧常驻 360px 分栏（非悬浮），标签条一键收起/展开；
   - 会话管理：标题下拉（新建/切换，当前项 ✓）、⋯ 菜单（压缩对话 / 删除对话）；
   - 对话流：用户/助手气泡、工具执行卡（含「自动批准」徽章 + 可展开输出）、审批卡（标题 + mono 命令 +「目标：<服务器>」+ 批准并运行 / 拒绝）；
   - 输入区：上行提示语 + 工具行（「+」添加上下文｜**策略胶囊**：始终询问 → 自动审查 → 自动批准循环｜内嵌模型选择器（含「管理模型…」直达设置）｜圆形发送钮）；
   - 执行期间输入排队（提示「助手正在执行…」），空闲时终端完全归用户；
   - AI 与终端**同一 SSH 会话**：批准的命令注入当前 shell stdin，上下文即屏幕 + 滚动缓冲；交互式提示（如 sudo）不代答，交还用户；
   - 本期工具集仅「在当前会话执行命令」。

**入口与到达路径**
- 主导航 → 终端域（无会话则空态引导）。
- 服务器域「连接 / 新建终端」→（连接对话框 ✅）→ 自动打开终端。
- 标签条 / 分屏按钮（形态由你设计）；AI 侧栏开关在终端域内。

**状态与异常**
- 无会话空态 ✅；连接中「正在启动终端…」✅；连接失败回退 + 重试 ✅；
- 远端 shell 退出/断线的呈现（当前实现未做检测，设计需给「会话已结束」的预期形态，列为开放项）；
- AI 执行中排队态、审批等待态、工具输出展开态（📋M5）。

**数据实体**：`ShellSession { id, serverId, title, pid? }`、`Tab { id, tree(分屏结构), active }`、`AiConversation { id, title, messages[], pendingApproval? }`

**实现状态**：✅ 1、3、核心状态与延迟；📋 2 的开关、4 的指标位、5、6、7 全部。

### 域 4 · 文件传输（SFTP）— 📋M2

**职责**：本地 ↔ 远程文件浏览与传输。

**功能清单**（全部愿景，B1–B4）
1. **双栏浏览**：本地栏 + 远程栏；列：名称 / 大小 / 修改时间。
2. 路径栏 + 后退 / 前进 / 刷新 / 搜索。
3. 上传 / 下载；传输队列：进度条 + 速度 + 剩余时间 + **取消**。
4. 同名冲突策略：每次询问 / 覆盖 / 重命名（可于设置配置）。
5. 新建文件夹、重命名、删除；传输完成通知。

**入口与到达路径**
- 服务器卡片「打开文件管理」（入口壳 ✅，落点为占位屏）→ 文件域。
- 规划中与终端共享标签条（原型愿景：文件作为标签页之一）——可达性由你的 IA 决定。
- 跨域拖拽入口（你可提案，无既有承诺）。

**状态与异常**
- 未连接/未选择目标的空态；单栏加载中；权限错误/路径不存在的错误呈现；传输失败与取消后的队列状态；传输中的离开提示（自由）。

**数据实体**：`RemoteFileEntry { name, isDir, sizeBytes, mtime }`、`TransferTask { id, direction(上传|下载), localPath, remotePath, progress, speedBps, etaSec, status(排队|进行|完成|失败|取消) }`

**实现状态**：📋 全域。布局须预留：双栏 + 底部传输条。

### 域 5 · 端口转发 — 📋M3

**职责**：通过 SSH 建立本地/远程/动态（SOCKS5）转发并管理其生命周期。

**功能清单**（全部愿景，C1/C2）
1. 三类转发：**本地监听 / 服务器监听 / 动态 SOCKS5**（类型切换）。
2. 转发表单：名称、类型、绑定地址、端口；「此计算机监听」主机+端口 ⇄「服务器网络目标」主机+端口。
3. 选项：「保存此配置」「连接时自动启动」。
4. 操作：开始转发 / 停止转发；开关切换自动启动。
5. 已保存的配置列表 + 活动转发列表（活动项须可见其绑定与归属连接）。
6. 活动转发计数角标（导航上的 badge）。

**入口与到达路径**
- 主导航独立入口（现状为 trailing 位，结构自由）；badge 数量来自活动转发。
- 通常依附某条已建立的 SSH 连接；跨域关联方式由你设计。

**状态与异常**
- 需先有连接才能启动（引导至连接）；端口占用/转发失败的错误呈现；空配置列表空态；活动项停止后的去留。

**数据实体**：`ForwardRule { id, type(本地|远程|SOCKS5), name, bindHost, bindPort, targetHost, targetPort, autoStart, active, connectionId? }`

**实现状态**：📋 全域。设计须覆盖：类型切换、表单、两组列表、badge。

### 域 6 · 仪表盘 — 📋M4

**职责**：所连主机的实时运行指标可视化。

**功能清单**（全部愿景，D3）
1. 四指标瓦片：CPU、内存、平均负载、运行时间。
2. 折线图：CPU / 内存 / 网络（收发双线）；磁盘用量条形（多分区，高用量告警色）。
3. 数据来源说明「数据来源：SSH 主机指标」；手动刷新；**10s 自动刷新**（数据经 SSH 采集 `/proc`、`df`、`uptime`）。
4. 服务器卡片上的微瓦片与本域同源（域 1 之 1）。

**入口与到达路径**
- 主导航独立入口（现状 Destination 壳存在，占位屏）。
- 服务器卡片「刷新统计/查看仪表盘」直达该主机（原型愿景）。

**状态与异常**
- 未连接任何主机：空态（引导去连接）；连接后加载中；单指标采集失败不影响其余指标；刷新中的非阻塞指示。

**数据实体**：`Metrics { cpuPct, loadAvg, memUsed/Total, uptimeSec, netRxBps, netTxBps, disks[{path, used, total}] }`（10s 快照序列用于画线）

**实现状态**：📋 全域。设计须给「无数据 / 单次快照 / 序列成线」三阶段形态。

### 域 7 · 设置

**职责**：全局配置中心。分类导航 + 单列内容（分类数与形态由你设计，愿景为 8 类）。

**功能清单**（按愿景分类；现状为占位屏）

| 分类 | 条目 | 状态 |
|---|---|---|
| 外观 | 主题（跟随系统 / 浅色 / 深色）、界面字体、界面缩放、显示语言（简体中文） | 📋（主题策略随视觉开放重定义，见 §1） |
| 终端 | 终端字体、终端主题（调色板）、选中即复制、Shift+Insert 粘贴、自动填入 sudo 密码 | 📋 |
